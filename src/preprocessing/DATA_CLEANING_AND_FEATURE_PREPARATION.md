# Data Cleaning and Feature Preparation

This document describes the executable V2 pipeline in [preprocess_v2.ipynb](preprocess_v2.ipynb). The design follows the problem definition in the [project specification](../../data/default_project.pdf) and the clinical and genotype guidance in the [IWPC supplementary appendix](../../data/appx.pdf). Its purpose is to convert the heterogeneous [raw patient table](../../data/warfarin.csv) into numeric, leakage-controlled feature sets for online bandit evaluation while retaining missingness whenever the absence of information may itself be informative.

## Cohort and target

The raw dataset contains 5,700 patients. The pipeline removes the 172 patients without a known therapeutic warfarin dose, leaving 5,528 observations. It preserves the original continuous weekly dose in `Therapeutic Dose of Warfarin__mg_week` for traceability, then creates the three bandit actions with cut points from the project specification: class 0 is below 21 mg/week, class 1 is 21 through 49 mg/week, and class 2 is above 49 mg/week. The resulting cohort contains 1,495 low-dose, 3,382 medium-dose, and 651 high-dose patients. This imbalance explains why the otherwise uninformed fixed policy obtains 61.18% accuracy by always choosing the medium arm.

The therapeutic dose is an outcome, never a patient feature. Both the bucketed label and continuous dose remain in the saved modeling table so evaluations can load labels from the same artifact, but the feature manifests explicitly exclude them. Any downstream experiment should select columns through [the feature manifest](../../output/preprocess_v2/warfarin_preprocess_v2_feature_sets.csv), not by taking every non-target column from the modeling CSV.

## Missingness is handled by meaning

V2 does not apply one blanket imputation rule. A missing demographic category is represented as unknown; a missing continuous body measurement is estimated; a missing genotype is imputed only when the appendix provides a defensible rule; and a medication status is set to non-use only where that convention is required by the dosing formulas. Missingness indicators accompany several imputed values so the bandit can distinguish an observed value from a replacement.

The contrast with the legacy preprocessing is clearest for gender. The older [preprocess.ipynb](preprocess.ipynb) filled every missing gender with `male`, which changes an unobserved attribute into an unsupported assertion and can distort any learned gender effect. Among the 5,528 modeled patients, V2 instead maps the four missing gender entries to the literal category `Unknown`. One-hot encoding therefore creates `Gender_female`, `Gender_male`, and `Gender_Unknown`; unknown gender is a visible model state, not a hidden substitution. Race and ethnicity follow the same principle. Their missing values are filled with `Unknown`, while values already recorded as `Unknown` remain unchanged.

Age has both numeric and categorical representations because different consumers need different forms. Thirty-nine patients have no age bucket. For numeric calculations, including the IWPC formulas and continuous interactions, V2 substitutes the cohort mode, `70 - 79`, and maps it to decade 7. At the same time it preserves `Age__missing`, creates an `Unknown` level in `Age__bucket_unknown`, and one-hot encodes that categorical representation. The model can therefore use a complete numeric age while still knowing which values were originally absent.

Most binary clinical and medication columns are converted from `1`, `0`, or missing into `Yes`, `No`, or `Unknown`, after which all three states are one-hot encoded. This treatment is used for diabetes, heart failure or cardiomyopathy, valve replacement, smoking, statins, aspirin, antibiotics, supplements, and the other binary clinical fields defined in the notebook. It avoids equating “not recorded” with “not present.”

Four medication variables receive different treatment because they feed the published dosing equations. Missing amiodarone is treated as non-use, matching the explicit convention in the IWPC appendix; V2 applies the same operational convention to carbamazepine, phenytoin, and rifampin or rifampicin when constructing enzyme-inducer status. The analyzed cohort contains 1,503 missing amiodarone entries and roughly 3,100 missing entries for each inducer component. Each is filled with zero, but a separate `__missing` flag is retained in the bandit feature matrix. `Enzyme inducer status` is then one when any of the three inducer drugs is recorded as used and zero otherwise. The IWPC formulas consume the cleaned status values, whereas the contextual bandits can additionally observe that a source field was missing.

## Genotype preparation

Missing CYP2C9 genotypes are not guessed. The 109 absent values are labeled `Unknown`, as are remaining missing genotype and consensus fields. V2 retains the full categorical genotype indicators and also derives compact numeric features: counts of `*2`, `*3`, all reduced-function alleles, and rarer non-`*1` alleles. An explicit unknown flag prevents an unobserved genotype, whose allele counts are necessarily zero, from being confused with a genuinely observed reference genotype.

VKORC1 rs9923231 receives the more specific treatment prescribed by section S4 of the [IWPC appendix](../../data/appx.pdf). Of the 1,633 missing rs9923231 values in the modeled cohort, the ordered decision list imputes 1,509 from rs2359612, rs9934438, or rs8050894. The rs2359612 and rs8050894 rules are race-gated because their linkage is weaker in Black patients; V2 also blocks those rules for missing or unknown race. The rs9934438 rules apply without that gate. The first applicable rule wins, exactly as the appendix specifies. The remaining 124 patients are labeled `Unknown` rather than assigned a genotype without support. The final representation includes the original categorical genotype, A- and G-allele counts, and an unknown indicator. Exact counts from each run are saved in the [VKORC1 imputation report](../../output/preprocess_v2/warfarin_preprocess_v2_vkorc1_imputation_report.json).

## Clinical context and text

The raw indication field may contain multiple treatment codes. V2 parses codes 1 through 8 into separate indicators for DVT, PE, atrial fibrillation or flutter, heart valve indications, cardiomyopathy or left-ventricular dilation, stroke, post-orthopedic use, and other indications. It also records whether the indication is unknown, whether multiple indications were supplied, and the number of recognized codes. The 697 missing indications therefore become an explicit unknown state rather than disappearing.

Target INR is treated as pre-treatment clinical context, which is distinct from the post-treatment field `INR on Reported Therapeutic Dose of Warfarin`. V2 extracts an exact target when available, parses lower and upper values from the estimated range, and uses the exact value first or the range midpoint second. If neither source is available, as occurs for 830 patients, it uses the cohort median of 2.5. Separate indicators record missing exact and range values, and the engineered features retain the lower bound, upper bound, midpoint, width, availability, and clinically useful intensity flags. The raw target-INR strings are dropped after these numeric replacements are created.

Comorbidity and medication text are not passed directly to a model. The pipeline normalizes case and punctuation, divides the text into clauses, ignores clauses containing common negations, and searches the remaining text for clinically grouped patterns such as thromboembolism, heart disease, renal or hepatic disease, cancer, aspirin, statins, amiodarone, antibiotics, azoles, and enzyme inducers. Missing text and explicit reports of no conditions or medications receive separate indicators. These regex-derived features are transparent and reproducible, but they are intentionally modest heuristics rather than a general clinical-language model. The original free-text columns are removed before numeric encoding.

## Height and weight

Height and weight are the only source of difference between the two active feature sets, but that difference propagates into every derived feature that depends on body size. In the modeled cohort, 839 patients lack height only, 30 lack weight only, and 242 lack both; 4,417 have both values. V2 retains flags for missing height, missing weight, and jointly missing height and weight before creating two complete alternatives.

The KNN branch standardizes height and weight, applies `KNNImputer(n_neighbors=5)` in that two-variable space, and transforms the results back to centimeters and kilograms. It can use an observed weight to help estimate height, or vice versa. When both values are absent, however, no patient-specific coordinate remains for calculating a meaningful neighbor distance, so the result is effectively driven toward the dataset-level center. This branch is retained as the direct continuation of the original project approach.

The regression branch uses `IterativeImputer` with Bayesian ridge regression, 20 iterations, median initialization, deterministic `random_state=42`, and no posterior sampling. Its predictors are age decade, male and female indicators, Asian, Black, and White race indicators, diabetes, heart failure or cardiomyopathy, and current smoking, together with height and weight themselves. An unknown demographic state is represented by zeros in the corresponding imputer indicators but remains explicitly represented later in the final bandit matrix. This branch can therefore estimate both height and weight from patient context when both measurements are missing.

Both branches are fitted once on the full 5,528-patient covariate table before patients are permuted for online evaluation. Neither imputer sees therapeutic dose, but this is a transductive preprocessing choice rather than a streaming imputer learned one patient at a time. Each completed branch produces height, weight, BMI, Mosteller body-surface area, and six body-size interactions involving age, CYP2C9, VKORC1, and enzyme-inducer status.

This confirms the relationship between the active sets. Each contains 295 features; 285 are identical. The remaining ten are the selected branch’s height, weight, BMI, BSA, and six body-size interactions. All demographic, clinical, medication, genotype, target-INR, text-derived, missingness, and non-body-size interaction features are otherwise exactly the same. The KNN set contains no regression-derived body-size columns, and the regression set contains no KNN-derived body-size columns. A group-median branch was considered during development but is not generated by the active notebook or present in the manifest.

## Encoding and leakage control

The notebook first writes a [raw-clean table](../../output/preprocess_v2/warfarin_preprocess_v2_raw_clean_table.csv) containing readable fields, identifiers, engineered features, both body-size branches, and outcomes for traceability. That file is not intended to be handed directly to a bandit. Before creating the numeric modeling table, V2 removes the subject identifier, empty unnamed columns, stable-dose status, INR measured on the reported therapeutic dose, raw free text, original age, original height and weight, raw indication, and raw target-INR strings. Engineered pre-treatment replacements remain.

All remaining object or categorical columns are encoded with `pandas.get_dummies(..., dummy_na=False, dtype=float)`. No reference level is dropped: gender, race, genotypes, and other categorical groups retain every observed level, including `Unknown`. `dummy_na=False` is appropriate because meaningful missing states have already been converted to explicit categories. Boolean columns are converted to numeric values, and an explicit intercept column of ones is added.

This differs from ordinary unregularized logistic regression, where one dummy is usually removed from each group to avoid exact collinearity with an intercept. The current bandits regularize their linear estimates: ridge gives a unique penalized solution, while L1 regularization selects sparse effects among correlated indicators. Their predictions can therefore use full dummy groups, but the coefficients are not comparisons against an omitted reference category and depend on the chosen regularization. The coefficient-audit utilities accordingly emphasize contrasts and clinically grouped signals rather than treating one isolated dummy coefficient as an absolute effect.

The resulting [modeling table](../../output/preprocess_v2/warfarin_preprocess_v2_modeling_table.csv) has 307 columns: both labels, both body-size branches, and all shared numeric features. The two 295-column experiment sets are defined separately in the manifest. Sanity checks assert that every selected feature exists, is numeric, contains no missing value, uses only its intended body-size branch, and excludes post-treatment outcomes and formula-derived predictions.

Standardization occurs later in [feature_set_benchmark.py](../evaluation/feature_set_benchmark.py), after one feature set has been selected. Every non-binary numeric feature is centered by its dataset mean and divided by its population standard deviation; binary indicators and the intercept are left unchanged. This scaling is used consistently across the Ridge, Hybrid, Lasso, and Linear Thompson Sampling evaluations.

## Baseline preparation

The fixed-dose policy requires no patient features or imputation. It assigns 35 mg/week to everyone, which is always the medium class.

The clinical IWPC formula uses age decade, height, weight, race, enzyme-inducer status, and amiodarone. Its age input uses the mode-imputed numeric decade; race preserves the published Asian, Black, and missing-or-mixed coefficients; medication inputs use the zero-filled statuses described above; and height and weight are evaluated once with the KNN branch and once with the regression branch.

The pharmacogenetic formula uses those same cleaned inputs and adds CYP2C9 and VKORC1 rs9923231. Missing CYP2C9 receives the appendix’s published unknown-genotype coefficient. VKORC1 uses the S4-imputed genotype where a rule applies and the published unknown coefficient for the unresolved 124 patients. Each formula predicts the square root of weekly dose, so V2 squares the result and then applies the same low, medium, and high cut points as the observed therapeutic dose.

These baseline calculations are reporting policies, not feature engineering for the contextual bandits. Their predicted doses and dose classes are never appended to the modeling table or feature manifests. The resulting accuracies are saved in the [formula-baseline report](../../output/preprocess_v2/warfarin_preprocess_v2_baseline_accuracy_by_hw_variant.csv), allowing the two imputation branches to be compared without leaking a published formula’s answer into the learned policy.

## Reproducibility artifacts

The notebook writes the raw missingness profile before cohort filtering, height/weight missingness after filtering, the VKORC1 decision-list report, category levels, body-size summaries, engineered-feature statistics, the raw-clean table, the numeric modeling table, and the final feature manifests to [output/preprocess_v2](../../output/preprocess_v2). Together, these files make the transformation inspectable without requiring a reader to reconstruct every notebook cell, while [preprocess_v2.ipynb](preprocess_v2.ipynb) remains the authoritative implementation.
